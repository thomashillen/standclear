# Rider UI and flow audit — October 27, 2026

Thomas requested a visual website review and tests of the overall rider experience. This audit follows **CALM INTERFACE, LIVELY MAP** and preserves the map-first, single-sheet model.

## Evidence and scope

Reviewed the live site at https://standclear.vercel.app in cloud Chromium at 382×580, including a rendered Mapbox map, station arrivals and a current-feed trip from 59 St-Columbus Circle to Times Sq-42 St. No uncaught page errors were observed. About, Status, line 1, Times Square station, Privacy, Terms and Changelog returned HTTP 200 and had no horizontal page overflow at that viewport. Public-page checks cover navigation/rendering, not the correctness or availability of every upstream health service.

The repeatable browser suite tests the production build at 382×580, 390×844, 594×368, 951×620 and 1280×800. Controlled train, alert and address-search responses exercise predictable states; real browser geolocation uses a synthetic Times Square position in a fresh, isolated context. Screenshots are inspected in addition to assertions. Live and fixture observations must not be conflated.

Validation passed: lint, explicit TypeScript, 981 component/unit tests across 94 files, production build and diff check. All 75 functional browser checkpoints passed across five viewport sizes. The compact run was repeated after adding contrast instrumentation and distinct public-page screenshot names; its 15 checkpoints passed. Four new component regressions fail against original main. These results do not clear the accessibility findings below.

This is representative flow coverage, not an exhaustive check of every station, route combination, localization, assistive technology or physical device.

## Prioritized remaining improvements

1. **Public arrival CTA contrast is too low.** On live `/line/1` and `/station/times-sq-42-st-127`, the 14px/600-weight “See live arrivals” links compute to `lab(83.9203 -48.7124 13.8849)` on white. Browser canvas conversion to sRGB yields `[94, 233, 181]`, giving **1.52:1** contrast against white, below the 4.5:1 normal-text criterion. MarketingShell’s descendant anchor color overrides the CTA’s intended dark text. Tracked in [#257](https://github.com/thomashillen/standclear/issues/257). Correct that interaction and add a contrast regression; preserve ordinary article-link styling.
2. **Station-to-line targets are too small.** Standalone line buttons in the Times Square station header measure 20×20px; the adjacent Directions, Favorite and Close controls are 44×44px. Increase their real, non-overlapping hit areas while preserving the MTA bullet artwork. Verify crowded interchange headers and available arrival-list height before choosing wrapping versus another arrangement. This audit records sizes rather than presenting those controls as an accessibility pass.
3. **Public-page header controls need the same mobile treatment as the map.** At 382×580 the Open app link measures 84.05×30px and GitHub 32×24px; both fall short of a 44px mobile target. The public header also sits at the top of the viewport; verify its behavior in the Duo home-screen app against the camera region. Browser containment alone does not prove physical cutout clearance.
4. **Home/Work discovery takes extra scrolling on the small screen.** In the 382×580 More sheet, System and Notifications push Commute below the initial fold. Scrolling works. Consider prioritizing frequent commute actions only after checking actual usage; this is a hierarchy/polish recommendation, not a broken navigation flow or authorization for a redesign.

The focus and endpoint fixes are deliberately narrow. This audit does not expand permissions, alter realtime freshness, add dependencies, change navigation architecture or redesign panels.

## Repeatable checks

Build and serve the app:

```sh
npm run build
npm run start -- --port 3001
```

In a QA environment with Playwright and Chromium available:

```sh
CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium \
UI_QA_OUTPUT=/tmp/standclear-ui-audit \
node scripts/check-rider-flows.mjs
```

The suite writes screenshots and `results.json`, including measured station/public-header targets and arrival CTA contrast. Functional passes do not imply that the recorded accessibility gaps pass. API fixtures are enabled by default. This is opt-in browser QA, not an undeclared dependency of `npm test` or GitHub CI. Existing component tests remain in CI.

To review a deployed site with actual API responses:

```sh
CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium \
UI_QA_ORIGIN=https://standclear.vercel.app UI_QA_LIVE=1 \
UI_QA_VIEWPORTS='[{"width":382,"height":580}]' \
UI_QA_OUTPUT=/tmp/standclear-ui-live \
node scripts/check-rider-flows.mjs
```

Live mode skips train/alert/geocode fixtures. It still uses synthetic browser GPS and isolated, ephemeral favorites/Home/Work. Failures may reflect live data/network state and must be investigated rather than dismissed or hidden.

Normal validation remains `npm run lint`, `npx tsc --noEmit`, `npm test`, `npm run build`, and `git diff --check`.

## Limits and device acceptance

Physical iPhone Duo Safari Add to Home Screen, native permission-dialog timing, camera occlusion, software keyboard/viewport resizing, VoiceOver announcements, Dynamic Type and touch ergonomics remain necessary. Reduced-motion browser checks do not establish native accessibility compliance. No native iOS SDK rendering or complete WCAG certification is claimed.
